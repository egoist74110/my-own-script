# RULES

## 核心原则
- 只实现用户明确提出的需求，不扩展功能
- 优先最小改动，避免无关重构
- 不修改无关文件
- 不引入新依赖，除非明确要求
- 不擅自优化代码结构（除非影响当前需求）

## 修改前
- 必须先阅读相关文件
- 理解现有实现方式后再修改
- 涉及不明确的第三方库或系统 API 时，必须优先搜索官方文档或可靠资料，严禁凭直觉猜测 API 参数、返回值或行为
- 优先复用已有函数 / hooks / 组件

## 修改中
- 保持与现有代码风格一致
- 避免大规模改动
- 每次只做一个明确目标的修改

## 高风险操作（必须提示）
- 修改公共组件
- 修改核心逻辑
- 删除文件
- 批量重构
- 修改配置文件（vite / webpack / tsconfig 等）

## 禁止行为
- 不得猜测需求并扩展实现
- 不得生成未被使用的代码
- 不得修改无关逻辑
- 不得创建“看起来更优雅”的替代实现
- 不得假设 Browser MCP 已可用、已连接或已连接到正确页面，必须先验证
- 不得在没有页面结构引用的情况下使用 Browser MCP 盲目点击或输入
- 不得编造 Browser MCP 联调结果、页面状态、console 日志或截图结果

## 红线（Flash gate 硬约束）
- **【禁止】** 在陌生仓库里，连续执行 > 3 次 Grep / Glob / Read 而没有先调一次 `bash "$HOME/.gemini/bin/ask-flash-read.sh"`
- **【禁止】** 一次并行发起 ≥ 5 个 Read 工具调用，除非 5 个文件的路径 + 函数名**全部已在本次对话的用户消息或之前工具结果中被明确给出**
- **【禁止】** 把"我 grep 一下就知道"、"我直觉就这 5 个文件" 当成"已知"——未经验证的判断不算已知，grep 本身就是 gate 要拦截的动作
- **豁免场景**（可以直接自己 Read / grep，不必过 Flash）：
  - 单文件、明确 bug、报错给了 file:line
  - 逐字精确的事：变量名、错误消息、配置值、版本号、类型签名、diff 对比
  - 已知文件数 ≤ 2 且满足上述"已知"定义

## 完成后
- 列出修改的文件
- 简要说明改动内容
- 指出潜在影响范围

## 前端联调补充规则
- 涉及前端页面、组件、交互、样式、路由、表单、弹窗相关修改时，完成代码后必须主动询问用户是否需要使用 Browser MCP 做页面联调或回归测试
- 未经用户明确同意，不默认执行 Browser MCP；如果需求已明确要求联调、回归、浏览器验证，可直接执行
- 使用 Browser MCP 时，必须先确认两件事：
  - Browser MCP server 已接入 AI 客户端并已 reload / 重启生效
  - 浏览器扩展已在目标 tab 上点击 `Connect`
- Browser MCP 的所有操作只针对当前已连接的 tab，不得猜测当前连接页面
- 联调结束后，必须如实汇报实际操作步骤、页面结果、console 情况和是否截图留证
