# VPN 直连规则与常驻修复（IPv4）

## 功能与边界

入口：**设置 → 服务 → VPN → 分流**。维护指定应用和固定 IPv4/CIDR 规则，通过更具体的目标路由走物理网卡；不修改 VPN 客户端。请确保这种分流符合所在组织的网络使用要求。VPN 若有包过滤或强制策略，仅修改路由不一定能绕过。

这是**目标 IP 分流，不是进程隔离**：应用规则用于发现目标，同一目标下其他应用也会受影响。只发现已连接 TCP/UDP 的远端 IPv4，不覆盖 IPv6、未连接 UDP 或未配置的辅助进程。已有连接可能需要重启目标应用才能使用新路由。

## 操作流程

1. 填写当前物理网关与网卡，添加应用精确可执行文件或真实 `.app` 路径，也可填写固定 IPv4/CIDR。没有预设任何软件安装路径。换网络后应重新确认网关与网卡，不要永久照抄示例。
2. 启用所需规则与总配置开关，**保存配置**。首次保存不安装助手，也不修改路由。预览只发现目标，不表示已生效。
3. 点 **授权安装并应用**，通过 macOS 的管理员授权弹窗安装系统助手、应用规则和启动常驻修复。不在应用中收集或保存管理员密码；不需要手填 Python 路径或复制脚本。
4. 查看实际状态与每个目标的路由校验。必须区分“已保存”“助手运行”“与当前配置同步”“目标路由已验证”。零目标、冲突、旧快照、过期心跳或检查失败都不能当作成功。
5. 安装后修改配置，**保存并同步**会更新助手快照；必要时再次出现系统授权。拒绝授权时配置可能已保存，但助手仍使用旧快照，界面须明确显示未同步，不能当作生效。
6. 点 **停用并撤销**：先停止系统守护，再撤销归属仍匹配的路由。操作不依赖当前物理网关有效；有未保存草稿也可停用。停用后不因工具箱重启或系统重启自动重新启用，需显式再次应用。

配置沿用既有数据目录 `config.json` 的 `vpn_bypass` 字段和全局 revision 乐观并发保护。刷新与状态轮询不应覆盖未保存草稿。应用、保存同步、停用等特权操作串行化；并发或版本冲突须先处理，不应对旧配置弹出授权。

## 安全与常驻行为

- 助手使用固定系统目录 `/Library/Application Support/toolbox-vpn-bypass`，launchd label `com.toolbox.vpn-bypass`。助手代码、配置和路由账本归 root 所有且普通用户不可写。公开诊断状态不包含密码或密钥。
- 特权操作仅经系统管理员授权；不修改 sudoers、不保存密码、不建立允许任意命令执行的常驻特权接口。解释器和运行时须可信；缺少合适运行时应明确失败，不临时下载或把用户可写的运行时当 root 服务启动。
- 守护脱离工具箱窗口运行，按配置间隔检查并补回缺失的自有路由；暂时断网、网关无效或应用发现失败时报告错误，不把失败解释为空路由表。动态目标有容量和保留期上限。
- 不覆盖第三方精确路由，不认领既有路由。撤销前刷新路由表，只有前缀、网关、网卡均仍匹配账本才删除。中断添加产生的 pending 条目无法证明归属时保留并提示人工核实；不要删除账本来“重置”。
- 后端结合 launchd、状态心跳、配置摘要与当前路由表校验，不仅凭“进程存在”或旧的成功记录判断健康。系统路由没有原子所有权标记，其他程序同时改路由仍有竞争风险，不应同时运行其他绕过管理器。
- 更新本机 `.app` 本身不会安装系统助手；首次应用必须通过独立的系统授权。离线导出仍只是专家备用入口，导出不等于安装。

## 验收

自动化测试 mock 所有提权和路由修改。真实验收需要检查：系统授权接受/取消、当前目标确实走物理网卡、VPN 保持连接、新节点发现、VPN 重连修复、工具箱关闭后常驻、助手重启/电脑重启、网络切换失败状态、保存同步、停用与第三方路由保留。未执行的场景必须在交付中列明，不用自动化通过代替真实路由验收。
