# 现代化重构：Agent 协作规范

状态：用户已确认协作方式；2026-10-21 起用于本仓库重构。规则仅作用于本项目，不自动安装工具或修改其他项目、用户全局配置。

## 1. 角色与模型

| 角色 | 用户指定的模型池 | 思考档位 | 责任 |
| --- | --- | --- | --- |
| 主控 | Opus 5.5 / GPT 6.1 Sol | Claude medium；GPT high | 决策、工作包、接口、优先级、集成验收 |
| 施工 | Sonnet 5.5 / GPT 6.1 Sol | medium | 限定范围实现、自检、委派测试、修复 |
| 测试子 agent | Haiku 5.5 / GPT 6 Luna | Claude medium；GPT 6 Luna high | 执行检查、补独立用例、复现和收集证据 |
| 交叉审计 | Opus 5.5 / Sonnet 5.5 / GPT 6.1 Sol；与施工方不同，优先另一厂商 | Claude medium；GPT 6.1 Sol high | 只读审查特定版本，登记有证据的发现 |

- 每个阶段有一个主控负责人。GPT 与 Claude 都可以主控；换主控时交接已接受决策、工作包、检查点和未解决问题。
- 型号名称是用户的路由要求，不能据此宣称本机已可调用。调度前核验真实运行时与支持的档位；没有指定型号则记录 unavailable，继续不依赖它的工作，不静默改用其他型号。
- Claude 一律 medium，包括审计与测试；GPT 6 Luna 一律 high。不得因节约成本自行降档。
- 当前调用工具不公开主控底层型号/档位时如实记录 unknown；这不等于缺少主控，但不得把目标配置当作实际署名。
- 原生子 agent 与外部 CLI 是不同调度通道。记录实际通道及会话 ID；不能把另一个 GPT 实例署名为 Claude。

## 2. 工作包是施工合同

主控先写明：编号、目标、依据、输入版本、依赖、已决定的接口、允许修改路径、禁止行为、验收命令、预期结果、语义验收、回退方式和升级条件。

- 一包对应一个可独立验证的业务结果，不按文件行数机械分包。
- 施工者可以自主决定范围内的局部实现，不改变已接受的需求、架构或接口。
- 遇到旧代码与事实不符，先提供证据；可以由主控修正包内实施细节，不把每次调整都转给用户。
- 共享模型、配置迁移和公共接口的更改由主控排序，调用方随同切换；不长期保留两套执行路径。
- 当前切片合同见 [WORK_PACKAGES.md](WORK_PACKAGES.md)，当前状态只认 [PROGRESS.md](PROGRESS.md)；已完成切片在 [archive/](archive/README.md)。
- **按需读取（省上下文）**：接手时只读 PROGRESS 全文（状态总表 + 跨切片待办 + 当前切片）与 WORK_PACKAGES 中当前切片相关的小节（先 `grep -n '^#\+ '` 列标题，再按行号读）。归档文件只在需要引用某个已决小节时打开对应的一个文件、读那一节，不整份通读。
- **切片收尾归档**：切片集成验收结论写定后，主控把该切片的合同与账本记录原样移入 `archive/work-packages/<切片>.md`、`archive/progress/<切片>.md`（相对链接改为 `../../`），更新 archive/README 索引，在 PROGRESS 状态总表留一行、把未关闭项并入「跨切片待办」。

## 3. 委派与并行

允许链路：主控 → 施工 → 测试。测试者和审计者不得继续派发 agent。

- 用户明确允许施工者开测试子 agent，此条优先于通用 task-orchestration 技能中“worker 不得派发”的默认约定；除此之外不递归扩张。
- 每包默认一个施工者、一个便宜测试者；不为凑模型数量重复验证同一内容。
- 同类失败连续两次后，把复现、尝试和差异交给主控调整方案，停止无证据的循环重试。
- 并行代码施工使用不同 worktree，路径所有权仍需明确。串行、只读测试可以在施工者的 worktree 执行。
- 测试子 agent 要补测试时，只能写包中指定的测试路径；施工者暂停修改这些路径。测试者不得改生产实现、删除失败测试、放宽断言或跳过检查换取通过。
- 主控集成后检查最终工作树；施工 worktree 的通过结果不能自动证明集成版本通过。
- 默认未授权提交时，由主控按限定路径的 patch 集成；应用前先核对基线用户脏文件清单和内容 SHA-256，已有文件先做 patch dry-run，新增文件必须确认目标不存在。发生重叠交回主控，不覆盖用户内容，不对共享工作树 stash/reset/checkout。仅集成不重叠的已核验增量。
- 默认不 commit/push/merge/publish/deploy；另有用户明确授权时才执行相应交付动作。

## 4. 测试与施工验收

测试者接收需求、接口契约、验收条件、差异边界及运行方法；不要只接收施工者的成功结论。

每次验证记录：工作包、代码版本（commit + dirty 文件内容摘要）、测试版本、模型/档位、命令、退出码、通过/失败/跳过数、关键输出、未测项和资源清理结果。

- 验收优先覆盖实际行为、故障路径和相邻调用，不堆镜像实现的测试。
- 缺依赖、无法调用、命令未执行和超时不能记成 pass。
- 指定测试者不可用时记录 unavailable；施工者自测写 `verified_by=executor, independent=false`，不能冒充独立测试。主控可继续无关包，并单列需要补齐的独立测试。
- 主控核对测试证据和范围，并亲自执行集成版本的必要检查。
- 真实 App 人工体验可后续集中补测，不阻塞已满足自动验收的独立工作；明确列出未测场景。
- 不使用生产发布、真实凭据变更、联网安装或清理用户文件来让测试通过。基线与回归使用隔离目录、假凭据和模拟远端。
- 不因测试者便宜就让它独立裁定权限、数据迁移或架构设计是否正确。

## 5. 交叉审计：异步、不阻塞

这是用户明确指定的项目工作流：审计不是工作包完成或下一包开始的前置条件。不强制每轮返工后重审，不要求问题清零才继续施工。

1. 主控在可审查的差异形成后，交给独立审计模型；优先跨厂商，无法实现时标明同厂商或 unavailable。
2. 审计者只读，不改代码、不再派发；注明审查 commit、dirty 内容摘要和范围。
3. 每条发现使用稳定编号，包含级别、文件行号、触发条件、证据、影响和最小修改方向。纯偏好不计为 bug。
4. 主控核实后登记 `open / fixed / rejected / deferred / blocked`，修复按影响和依赖排入后续包；不阻塞不相关工作。
5. 修复后先执行有针对性的回归；需要复核时优先继续原审计会话，保留发现编号。会话无法续接时标明连续性中断，新会话是替代审计，不能冒充原轮次。
6. 审计没有返回就是 pending；调用失败是 unavailable，未审查的新代码是 not_reviewed，不能混成审计通过。

技术严重度仍应如实表达，但审计模型不能自行增加“必须审到通过”的施工门禁。真实发布、删除业务/数据和权限扩张仍遵守用户原有授权边界；这与异步审计分开处理。

## 6. 署名与账本

署名集中在工作包完成记录、测试记录、审计记录与后续提交说明，不给每个源码文件加模型签名。

```text
工作包：WP-...
角色：主控 / 施工 / 测试 / 审计
requested_model / requested_effort：要求的调度配置
actual_model / actual_effort：可验证的运行值；不可验证写 unknown
evidence_source：提供方/运行时元数据、CLI会话回执或显式调度参数；模型自述不算证据
runtime_identity / agent_or_session_id：实际运行通道与可续接标识
source_revision：commit + dirty 文件 SHA-256 清单或差异摘要
changed：路径列表
verification：命令、退出码、关键结果
not_run / deviations / findings：未测、偏差、问题编号
cleanup：临时进程/目录的处置
```

显式调度参数证明 requested 配置与运行时接受了该请求；只有返回元数据/会话回执明确提供的字段才记为实际核验值。没有提供方回执的原生子 agent，其 actual 字段写 unknown，并保留请求参数与 agent ID。

正文保留非敏感结论。运行时绝对路径、原始工具输出和会话缓存留在 git 忽略的本地审计目录；不提交凭据、用户配置或原生会话缓存。

## 7. 升级边界

施工和测试发现问题先交主控。只有以下情况才找用户：新的高影响需求/架构取舍、扩大整体写入范围或权限、安装新外部工具、删除业务或用户数据、真实发布，以及无法在既定约束下继续的必要外部条件。

模型调用失败不伪造结果，不自动扩大权限；已有授权覆盖的常规修复、测试和审计无需重复询问。

历史 `config/model_collaboration_templates/` 中的“自检即可交付”“不要自动复审”“固定 Flash gate”等条款不覆盖本规范；本项目以角色、范围和证据分工，不按读取次数强制调用特定旧模型。模板复制到其他项目时须另行适配。
