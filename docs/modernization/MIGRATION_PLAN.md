## 1. 两个文件夹

| 文件夹 | 分支 | 用途 |
| --- | --- | --- |
| `/Users/wesker/my-own-script` | `main` | 旧应用，日常使用；`.app` 包装指向这里。只接受必要热修。 |
| `/Users/wesker/my-own-script-next` | `rewrite/next` | 新产品在 `next/` 下开发；同目录的旧代码只作参考，不改。 |

规则：

- 新代码不 import 旧包（避免带入 Qt）；需要时拷贝改写并补测试。
- 旧应用的热修在 `main` 上完成；涉及的业务规则同步记录，由对应切片在新后端实现，不靠 git 合并旧 UI 代码。
- 新应用在 S9 前只以开发模式运行，不覆盖旧 `.app`，不修改旧配置（见架构 §5）。

## 3. 每个切片的“搬完”标准

1. 对照旧能力文档（`docs/capabilities/*.md`）列出功能清单，逐项标 迁移 / 改进 / 有意放弃（放弃需用户确认）。
2. 后端：应用服务单测 + 外部适配器契约测试（假凭据、MockTransport、假进程）；旧缺陷的表征场景转为正确行为回归。
3. 前端：组件测试 + Playwright（MSW 模拟后端）覆盖主流程与错误态。
4. 资源所有权切换步骤写明（停用旧应用中的对应开关），由用户执行或确认。
5. 用户在真实应用中验收；未测场景写入账本。

| 包 | 处置建议 | 理由 |

| WP-11 附件认证边界（D01） | 在旧应用 `main` 上最小热修 | 每天在用，PAT 可能发到外部 host；新后端 S2 按同规则实现 |

| WP-16 外部接口契约 | 保留，作为 S6/S7 的前置调查 | 与 UI 技术无关 |
