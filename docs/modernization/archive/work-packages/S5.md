### 状态模型

- 会话 `state`：`starting → idle ⇄ busy → (awaiting_approval ⇄ busy) → closing → ended`；`failed`（启动失败，终态）。`ended.reason ∈ user_closed|process_exited|interrupted_on_exit|backend_restart|start_failed|limit`；`exit_code`。所有转换只由 AISessionService 的单一会话任务执行；外部调用只投递命令。
- 回合 `turn`（headless）：`queued → running → completed|failed|interrupted`；Codex/agy 每回合一个进程，进程退出即回合终态（无 `turn.completed` 时按退出码补记）。
- 审批：`pending → allowed|denied|expired`（终态，原子消费一次）；会话结束/中断时 pending → expired。
- 不变式：①进程表中每个存活进程恰好对应一个非终态会话；会话进入终态时其进程组已不存在（或已登记为 `kill_failed` 并在 UI 显示）。②每个回合只有一个终态事件。③一个审批只被决定一次，决定后才写回 CLI。④已结束会话不再产生 TG 消息。

### AI 子进程所有权与生命周期（D09）

- **主控修订（2026-10-23，S5-A 第 1 轮交回）**：监督器与 CLI 分属不同进程组——监督器由后端 `start_new_session=True` 启动；CLI 在监督器 fork 出的子进程内 `setpgid(0,0)`（PTY 模式 `setsid`+`TIOCSCTTY`），监督器杀 CLI 组后继续 `waitpid`；下文“于自身进程组内”以此为准。env 过滤按 `_` 切段：任一段为 `TOKEN|TOKENS|SECRET|SECRETS|PASSWORD|PASSWD|PAT|COOKIE|COOKIES`，或整名含 `API_KEY|APIKEY|ACCESS_KEY|PRIVATE_KEY` 或子串 `TOKEN|SECRET|PASSWORD` 即删；`PATH/MANPATH/INFOPATH/FPATH` 永不删；PATH 补全目录可注入（测试注入替身目录）。
- **不在后端进程内 `os.fork()`**。统一经 `subprocess.Popen(start_new_session=True)` 启动 `python -m toolbox_backend.adapters.proc_supervisor`（单线程，可安全 fork）：参数为控制管道 fd、模式（pipe/pty）、cwd、argv（JSON 经 stdin 传入，不放 argv）；监督器 fork CLI 子进程于自身进程组内、等待其退出、控制管道 EOF 或收到 stop 指令时 TERM 进程组 → 3 秒 → KILL → `wait`，并清理已退出直接子进程留下的后代（同 `git_process.py:22–38` 语义）。主动 `setsid` 脱离进程组的后代不在回收范围，合同如实记为限制。
- PTY 模式：后端 `pty.openpty()`，slave 作为监督器 stdio，监督器 `setsid` + `TIOCSCTTY` 后 fork CLI；master fd 由后端 asyncio 读（非阻塞，单次 64 KiB），`TIOCSWINSZ` 由后端设置；rows 5..300、cols 20..500。
- 环境变量：继承后端环境后**删除** `TOOLBOX_*`、`CI`、以及名字匹配 `(?i)(TOKEN|SECRET|PASSWORD|PAT|API_KEY|COOKIE)` 的变量（用户 shell 中真实需要的变量由 CLI 自己的配置文件提供）；补全 PATH；设 `TERM=xterm-256color`（PTY 另设 `COLORTERM=truecolor`）。**不向 CLI 注入任何 PAT/Bot Token**；ADO MCP 由 CLI 侧自行配置（S6 前沿用旧注册，待决8）。
- cwd：创建时把 `repo_id` 解析为 `realpath`，必须是存在的目录且属于当时的 `ado.local_repos`；目录不存在 409 `repo_missing`，不回落到其他目录。监督器 `chdir` 失败即 `start_failed`。
- 关窗：隐藏到菜单栏，会话继续（后端存活）；页面刷新只断开订阅。**退出**（后端 shutdown）：AISessionService 先拒绝新会话 → 所有会话并行：Claude 关 stdin、每轮型与 PTY 发 TERM 组 → 统一等 3 秒 → 关闭控制管道（监督器 KILL）→ 再等 ≤2 秒；未结束的标 `kill_failed` 记日志；整体 ≤5 秒。会话置 `ended(interrupted_on_exit)`，保留 `external_id` 供下次续聊。lifespan 顺序：RunService → AISessionService → TelegramService（AI 结束提示可入箱，发送随 Telegram 停止保留 pending）。
- 输出读取永不被下游阻塞：读任务只写事件库与内存总线（有界队列 256，满则向订阅者发 `overflow` 并要求按 seq 重拉）；TG 投影器独立消费（D11）。单行 stream-json ≤4 MiB，超出丢弃该行并记 `error(line_too_long)`；stderr 只保留最近 64 KiB 环形缓冲、脱敏后按行入事件（≤2000 字/行，每秒 ≤20 行，超出合并计数）。
- 超时：Codex 每回合 30 分钟、agy 每回合按 `--print-timeout` 默认 10 分钟（进程看门狗多 60 秒）；Claude 常驻无回合超时，空闲 4 小时自动关闭（可续聊）；升级命令 600 秒；检测命令 15 秒；`agy models` 20 秒、缓存 10 分钟。
