# VPN 分流助手：安装、运行与故障处理

## 正常使用（无需手工脚本）

打开 **设置 → 服务 → VPN → 分流**：

1. 填写物理网关和 `enN` 网卡，添加真实应用路径或 IPv4/CIDR；启用并保存。
2. 首次点 **授权安装并应用**，在 macOS 系统授权弹窗确认。工具箱不收集、保存或代填管理员密码。
3. 查看助手运行、配置同步、最近检查及逐目标路由结果。只有当前路由校验通过才表示该目标直连；零目标不是成功。
4. 安装后修改规则点 **保存并同步**，必要时再次授权。拒绝授权可能是“配置保存了，但系统助手未更新”，应重新应用，而不是把保存消息当作路由成功。
5. **停用并撤销**先停止守护，再撤销仍能确认归属的路由；不删除其他程序的路由。未保存草稿或当前网关失效不妨碍撤销。

构建或安装 `.app` 不自动安装 root 助手。第一次应用单独授权；之后由 LaunchDaemon 常驻，不依赖工具箱窗口。停用后应保持停止，直到显式重新应用。

## 文件与权限

固定目录：`/Library/Application Support/toolbox-vpn-bypass`。

- `helper.py`：独立标准库脚本，root 持有，普通用户不可写。
- `config.json`：已应用的配置快照，私有。
- `state.json`：动态目标缓存和路由归属账本，私有、原子写入并 fsync；**不要手工删除来清错**。
- `lock`：对账、循环、撤销之间的互斥锁。
- `status.json`：非密诊断状态，供普通权限后端读取；不是控制接口。
- `/Library/LaunchDaemons/com.toolbox.vpn-bypass.plist`：固定 label `com.toolbox.vpn-bypass`，按配置扫描周期运行。

父目录、助手、解释器及运行时必须满足可信 root 路径要求；拒绝用户可写目录及危险符号链接。系统授权执行内置安装逻辑，不以 root 执行用户临时目录里的安装脚本。不修改 sudoers，也不建立允许任意命令的 root IPC 服务。

助手仅用标准库，兼容 Python 3.9 及以上，与后端的 Python 3.14 环境分离。应用自动寻找并校验可信系统运行时；macOS 不保证自带 Python，运行时缺失或校验不通过须明确报告，不能盲用 Homebrew/uv 的用户可写解释器，也不会自动下载安装运行时。`-I -S` 隔离用户环境和 site 包。

## 状态的含义

后端综合检查 launchd 运行状态、心跳新鲜度、已安装快照与当前配置摘要，以及当前系统路由表。仅有进程、历史成功记录或配置启用开关均不能证明成功。

- **未安装**：只保存了配置，尚无可用系统助手。
- **待应用 / 未同步**：已保存配置与系统快照不同，或尚未完成一次有效检查。
- **运行 / 已验证**：服务正在运行，状态新鲜且配置匹配，目标的实际网关与网卡均通过校验。
- **降级 / 错误**：无目标、路由冲突、网关无效、过期心跳或检查失败；查看具体错误。
- **已停止**：服务不再运行；还需确认撤销结果，不把停止本身当作路由清理成功。

## 路由安全规则

规则是目标 IPv4 分流，影响同一地址的所有应用；不是进程级隔离，不覆盖 IPv6。应用仅匹配内核报告的精确可执行路径；`.app` 解析 `CFBundleExecutable`，辅助进程需另列。只发现已连接 TCP/UDP 的远端 IPv4；未连接 UDP、IPv6、未配置的辅助程序不会被发现。老连接可能需重启目标应用。

网关必须在活动的物理 `enN` 端口上存在 on-link 路由，不从被 VPN 改写的默认路由猜测。换网络后重新确认配置；暂时断网时应显示错误，守护继续尝试恢复。

添加前持久化 pending 账本，添加后重新读取路由表验证。只有确认由本助手添加且前缀、网关、网卡仍一致的路由才可撤销。崩溃留下的 pending 条目若已经存在精确路由，归属不明，不擅自认领或删除。已有第三方精确路由即使网关相同也报告冲突，不覆盖。系统路由没有原子所有权标记，同时运行其他路由管理工具仍有竞争风险。

## 故障处理与只读诊断

```bash
launchctl print system/com.toolbox.vpn-bypass
route -n get <实际目标IPv4>
```

使用界面本次发现的目标，不照抄历史 IP。真实生效时应走所配物理网卡与网关；仍走 `utunN` 不能算成功。系统路由校验通过也不能保证 VPN 的包过滤允许该流量，仍需测试目标应用实际可用性。

- 授权取消：不自动绕过授权，重新点击应用即可。
- 保存后未同步：处理系统授权或运行时错误，再重新应用。
- 路由冲突 / pending：不要强删账本；先检查其他路由管理器和实际目标路由，人工确认归属。
- 网络变化：确认新物理网关与网卡，保存同步；撤销不应依赖旧网关仍在线。
- 停用错误：保留账本和安装文件，核查残留，不能直接删除目录宣称撤销成功。

## 备用离线导出

`export_vpn_bypass.py --help` 与 `/api/vpn/bypass/export` 保留给管理员审查、离线安装使用。它们只生成文本，不代表安装或生效。正常界面流程不需要填写 Python 路径或复制脚本。

## 验证边界

自动化测试 mock 提权、launchd 与路由操作。真实场景包括授权接受/取消、当前目标直连、VPN 重连修复、新节点发现、关闭工具箱后持续运行、系统重启、换网络、保存同步与撤销。交付时分别列明实测与未测，不把测试通过当作全部场景验收完成。
